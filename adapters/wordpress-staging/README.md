# WordPress staging adapter\n\nReusable staging transport/runtime implementation for the framework. It supports `local` or `ssh` transport, and `host-wpcli` or `docker-compose-wordpress` runtime. Docker Compose addressing is always by Compose project + stable service name; concrete container names are never part of the contract.\n\nMutating commands call the target WordPress runtime's `wp_get_environment_type()` gate first. The config's `environment` label is descriptive and is not sufficient to authorize writes.\n\n`docker-compose-wordpress` first uses WP-CLI inside the WordPress service when available. Otherwise it launches the official `wordpress:cli` image with the WordPress service volumes, Docker network, and only the four required `WORDPRESS_DB_*` values in a mode-0600 temporary env file that is always deleted.\n
