# 日常框架改进任务

使用 factory-maintainer。本次任务由用户提供具体 Issue 编号；若用户明确授权按路线图推进，则选第一个依赖已满足的未完成项。

先读取 AGENTS.md、CONTRIBUTING.md、ROADMAP.md、CHANGELOG.md，以及当前 Issue 和相关测试。
确认这是框架问题；站点特有的内容/样式问题不要回流成通用硬编码。

在新分支 feat/<issue>-<slug> 或 fix/<issue>-<slug> 中工作，保留用户未提交内容。
先输出目标、非目标、接口和验收，再实施一个可合并的最小改动。
新增自有最小复现/失败测试 → 修复 → 完整回归；补充至少一个错误输入/拒绝路径用例。
若改 Skills，用相同 fixture 和可记录的 Agent/浏览器环境验证，不把单元测试通过等同于模型行为改善。

更新相关 Skill、文档、CHANGELOG 和兼容性说明。不要每轮把整套规范重写一遍。
禁止修改基准、放宽阈值、删用例或伪造报告来通过。
涉及门禁、权限、CI 或发布的变更明确标记并等待维护者审阅。

运行本地检查，审阅暂存区，再推送当前分支并创建 Draft PR。
PR 写明 Issue、测试结果、证据、旧站点影响、升级方式、回滚方式及未验证项。
读取实际 CI 结果；在此 PR 内有界修复，失败时保留明确原因，不无限刷 PR。
不自动合并、不自动创建 release、不更新所有站点、不执行生产发布。
